서명 작업실

Word 파일 하나를 끌어놓고, 서명할 영역을 드래그해 크게 쓴 손글씨를 넣은 뒤 DOCX 사본으로 저장합니다. 미리보기와 Word의 줄바꿈이 달라 서명이 밀리는 문제를 원본 글자와 줄에 연결해 개선했습니다.

내가 한 일

사용자가 직접 작성 영역을 정하고 원문 서식을 보존해야 한다는 요구를 정리했습니다. 사용자 피드백을 바탕으로 Word 단독 입력을 기본으로 삼고, 위치 오류를 재현해 검증 기준을 바꿨습니다. 구현과 자동화 스크립트 작성에는 AI 개발 도구를 활용했습니다.

개발 과정

PDF에서 출발

드래그 영역을 페이지 비율로 저장하고, Canvas에서 작성한 이미지를 비율에 맞춰 원본 PDF 페이지 위에 추가했습니다.

Word 파일 하나로 줄이기

0.2는 위치 기준으로 같은 문서의 PDF를 함께 받았습니다. 별도 파일을 준비해야 한다는 피드백을 반영해 0.3부터 브라우저에서 DOCX 미리보기를 만들고 Word 사본을 바로 저장했습니다.

원본 보존

미리보기용 표식은 사본에 넣습니다. 원본 파일은 유지하고 사본의 DOCX에 서명 PNG를 텍스트 앞 부동 그림으로 삽입합니다. 합성 문서에서 본문과 표, 밑줄 서식 보존을 확인했습니다.

기기 안에서 문서 처리

열기, 미리보기, 필기, 파일 저장을 기기 안에서 처리합니다. 웹은 다운로드, Windows 앱은 운영체제 저장창을 사용합니다.

트러블슈팅

저장한 Word에서 위로 밀린 서명

증상
미리보기에서 서명 칸에 놓은 이미지가 저장본에서 위쪽에 나타났습니다. 초기 테스트는 본문 보존과 그림 존재를 확인했지만 목표 줄과의 거리를 재지 않았습니다.
원인
브라우저 미리보기와 Word에서 본문 줄 높이와 쪽 나눔이 달랐습니다. 미리보기의 페이지 좌표를 그대로 쓰면 그 차이가 쌓였습니다.
수정
0.3.1에서 서명의 세로 위치를 가까운 문단에 연결했습니다. 0.3.2에서는 여러 줄 문단과 표 셀을 다루기 위해 미리보기의 글자를 원본 DOCX XML에 매핑하고, 가로는 글자, 세로는 줄 기준으로 그림을 배치했습니다. 화면에는 연결된 글자를 초록색으로 표시합니다.
회귀 검증
합성 문서의 목표 글자를 정하고 실제 Word에서 그림 앵커를 확인했습니다. 미리보기에서 2쪽, Word에서 3쪽이 된 자동 쪽 나눔 사례에서도 그림은 목표 글자가 있는 Word 쪽을 따라갔습니다.

남은 검증

  • 브라우저와 Word의 페이지 구성은 문서에 따라 다릅니다. 혼합 글꼴, 글상자, 머리글·바닥글, 복잡한 필드와 다른 PC·Word 버전의 시각적 결과는 추가 검증이 필요합니다.
  • Windows 실행 파일과 설치 파일을 빌드했습니다. 실제 설치와 운영체제 저장창은 수동 확인이 남아 있습니다.
  • 기존 자필 이미지 재편집과 초안 자동저장은 후속 과제입니다.
