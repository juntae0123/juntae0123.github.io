개요

사람이 손에 드는 핸들로 작업을 보여주면, 그 시연을 학습한 정책이 소형 로봇팔(SO-101, 5자유도 + 그리퍼)로 같은 작업을 합니다. 저는 정책 모델의 학습과 평가를 맡았고, 일정이 줄면서 시뮬레이션 환경, 실 시연 데이터 조립, 실물 배포와 디버깅까지 맡았습니다.

내가 한 일

  • 평가 기준을 먼저 고정 — 착수 첫날 평가 지표를 검증 손실이 아니라 롤아웃 성공률로 정하고, 통과 기준(100회 중 20% 초과)을 결과를 보기 전에 코드 상수로 박았습니다.
  • 정책 학습 — 행동 복제(BC)에서 시작해 DAgger와 행동 청킹을 조합했고, 각각 단독으로는 0.3%와 8.0%였지만 함께 쓰자 63.7%로 기준을 처음 넘었습니다. 이후 공식 UMI Diffusion Policy로 바꿔 최종 모델로 썼습니다.
  • 시뮬레이션 환경 — 원래 다른 트랙 몫이던 MuJoCo 씬을 만들었습니다. 관절 범위 대조, 카메라 배치, 그리퍼 패드 관통(14.6mm → 3.0mm) 수정까지 했습니다.
  • 실 시연 데이터 — 수집 품질 검사(92편 중 90편 합격), SLAM 결과 검산, 학습 데이터 변환을 거쳐 학습 가능한 형태로 조립했습니다.
  • 실물 배포 — 학습한 정책을 TorchScript로 묶어 Jetson에 올리고, 실물 실행부를 디버깅했습니다. 실행 로그 판정기, 시작 자세 정렬 도구를 만들었습니다.

트러블슈팅

손실은 내려가는데 성공률이 0%였다

상황
첫 학습에서 검증 손실이 0.00547에서 0.00517로 내려갔는데 시뮬레이션 성공률은 0%였고, 독립 학습 두 번에서 똑같았습니다. 사흘 동안 원인 설명이 세 번 바뀌었고 셋 다 틀렸습니다.
원인을 좁힌 과정
추측을 멈추고 원인 후보를 셋으로 가르는 계측기를 만들었습니다. 기록된 행동을 그대로 재생하면 성공했고, 정답 관측을 넣고 다음 동작만 물으면 예측은 정상 수준이었으며, 실제 실행 첫 스텝에서는 같은 관측인데 출력이 달랐습니다. 학습 경로와 추론 경로를 대조하니 학습 때는 표준화를 하지 않고 추론 때만 역표준화를 하고 있었습니다.
해결 · 결과
경로를 맞추자 0%에서 5.7%(17/300)로 올랐습니다. 이후 기록한 계측기 결함 20여 건이 전부 결과를 좋게 보이게 하는 쪽이어서, 계측기 안티패턴 8종을 검사하는 스크립트를 만들어 계측 코드 116개 파일에 돌렸습니다.
배운 점
검사를 느슨하게 만드는 실수는 통과를 만들어서 눈에 띄지 않습니다. 계측기에도 정답을 아는 입력으로 자체 검사를 붙입니다.

정책이 제자리에 멈춰 있었다

상황
검증 손실은 낮은데 롤아웃이 300회 중 0회 성공이었고, 로봇이 거의 움직이지 않았습니다.
원인을 좁힌 과정
씬·카메라·변주·제어 주기·이미지·모델 용량 6개를 하나씩 계측해 배제했습니다. 결정적 단서는 조건을 무엇으로 바꿔도 "잡는 순간 물체까지 거리"가 158mm 근처로 같다는 점이었습니다. 데이터 내용이 아니라 형식 문제였습니다. 행동 라벨이 "다음 시점의 상태", 즉 이미 간 거리로 정의돼 있어 관측 없이도 87~94% 예측됐습니다.
해결 · 결과
행동 라벨을 실제 제어 목표로 바꿨습니다. 성공 0/300 → 22/300(7.3%), 잡는 순간 거리 158mm → 45mm.
배운 점
여러 조건에서 같은 값이 나오면 조건이 아니라 정의를 의심합니다.

실물 팔이 조금씩 처져 내려갔다

상황
실물에서 동작이 반복될수록 팔 높이가 명령보다 낮아져, 런마다 2.8~10.3mm씩 처졌습니다.
원인을 좁힌 과정
접근 축, 정책의 하강 명령, 좌표계 회전 세 가설을 순기구학 계산으로 기각했습니다. 실행부 코드를 따로 재구현해 원본과 비교(잔차 0.0074mm)하자, 모터가 목표에 도달하기 전에 다음 명령을 보내는 설정 때문에 상대 명령이 낮은 관측값 위에 누적되고 있었습니다.
해결 · 결과
남은 오차만큼 다시 명령하는 패치를 넣어 처짐을 1.1~2.7mm로 줄였습니다(목표 3mm 이내).
배운 점
정책이 아니라 실행부가 원인일 수 있다는 걸 재구현으로 확인했습니다.

학습 데이터에서 잡는 장면이 지워지고 있었다

상황
실 시연을 학습 형식으로 변환한 데이터에서 집게가 닫히는 구간이 보이지 않았습니다.
원인을 좁힌 과정
데이터 변환 단계의 기본 설정이 시연 앞부분 3초를 잘라내고 있었습니다. 같은 10편으로 비교하니 잘라낸 데이터에서는 집게 닫힘이 0/10, 자르지 않은 데이터에서는 10/10이었습니다. 지워진 프레임 수(900 = 90프레임 × 10편)가 정확히 3초와 맞았습니다.
해결 · 결과
학습 설정에 자르기 0초를 명시하고 결정 기록에 되돌릴 조건과 함께 남겼습니다.
배운 점
기본값은 설정을 안 한 것이 아니라 누군가 정해 둔 값입니다.
